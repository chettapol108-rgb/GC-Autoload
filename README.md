# GC-Autoload
VB code which have to be pasted into .xlam file again for showing as a ribbon in Excel

## ประมวลผลทุก SKU แยกตาม Platform (v3.5.1)

Translate Input, Load Data และ Export XML ใช้ทุก SKU ที่พบใน input ของ platform ที่เลือก ไม่มีช่องเลือก SKU และค่าพรีวิวสำเนาที่ต้องเปลี่ยนทีละ SKU และไม่จำเป็นต้องเรียง SKU ติดกัน

กำหนด `AutoLoad-Input!B2` เป็น `SP` สำหรับแถวที่คอลัมน์ C เท่ากับ `Shopee` (ไม่สนตัวพิมพ์เล็กใหญ่และช่องว่างหัวท้าย) หรือ `TT` สำหรับค่าอื่นที่ไม่ใช่ Shopee รวม TikTok, Facebook และค่าว่าง หรือเลือก `ALL` เพื่อประมวลผลทุกแถวโดยไม่กรองค่าในคอลัมน์ C วันที่และ SHOP/FN ของผลลัพธ์ใช้ A2 และรหัส SP/TT/ALL จาก B2 เหมือนกันทั้งรอบ ไม่ได้ใช้วันที่รายออร์เดอร์จาก ERP

หัว DATE อยู่ A1 และ PLATFORM อยู่ B1 โดยกรอก Date ที่ A2 และ Platform ที่ B2 หัวตารางข้อมูลอยู่แถว 3 และข้อมูลเริ่มแถว 4 ตามโครงสร้างใหม่:

| คอลัมน์ | ข้อมูล |
|---|---|
| A | SKU |
| B | Barcode (Order ID) — วางเป็น Text เพื่อรักษาศูนย์นำหน้าและเลขยาว |
| C | PLATFORM เช่น Shopee, TikTok, Facebook |
| D | จำนวน (หัวตารางแถว 3 ใช้ `จำนวน` หรือ `Qty`) |
| E | Raw Input |

หัว C3 ต้องเป็น `PLATFORM` และ E3 เป็น `Raw Input` เทมเพลตเก่าที่ใช้ C=จำนวน, D=Raw Input ต้องเพิ่มคอลัมน์ Platform ก่อนใช้งาน ไม่ใช่การวาง ERP ทั้งตารางโดยตรง

ชีต `Database` ต้องมีหัวแถว 1 ตามลำดับ A:H = `SKU, Set, Name A, Name B, Name C, Name D, OID, Barcode` ระบบค้น SKU แบบไม่สนตัวพิมพ์เล็กใหญ่และช่องว่างหัวท้าย อ่าน B:H เป็นค่าตั้งของแต่ละ SKU โดยตรง ไม่ต้องมีช่องเลือก SKU หรือสูตร VLOOKUP สำเนาใน AutoLoad-Input และไม่ใช้คอลัมน์ I ของ Database กรอง platform ต้องมี SKU ตรงกันเพียงรายการเดียว, Set เป็นจำนวนเต็มบวก, สำเนาทุกประเภทเป็นจำนวนเต็มตั้งแต่ศูนย์ และต้องมีสำเนาผลลัพธ์อย่างน้อยหนึ่งประเภท

1. เลือก B2 และกำหนด A2 แล้วกด **Translate Input** ระบบกรอง platform ก่อนรวม Order ID + SKU ตรวจจำนวนและแปลชื่อด้วยกติกาเดิม เขียน NormalizedInput A:H รวมทุก SKU หากมีกลุ่มผิดพลาด จะไฮไลต์และรายงานข้อผิดพลาด; ต้องแก้แล้ว Translate ให้สำเร็จก่อน Load/XML แม้มีกลุ่มอื่นแปลสำเร็จแล้ว
2. กด **Load Data** ระบบตรวจค่าตั้งและชีตปลายทางของทุก SKU ก่อนล้างผลลัพธ์ จากนั้นเขียนแต่ละ SKU ตามจำนวนชุดและสำเนาของตัวเอง ชีต SKU ที่ไม่มีข้อมูลในรอบนี้ไม่ถูกล้างหรือส่งออก ถ้าระหว่างเขียนเกิด runtime error บางชีตอาจเขียนไปแล้ว ต้องแก้ปัญหาและ Load Data ใหม่ให้สำเร็จทั้งรอบ
3. กด **Export XML** เลือกโฟลเดอร์ครั้งเดียว ระบบสร้างโฟลเดอร์ย่อย `AutoLoad-SP-yyyymmdd-hhnnss` , `AutoLoad-TT-...` หรือ `AutoLoad-ALL-...` พร้อมไฟล์ `<SKU>.xml` แยกทุก SKU ของรอบนี้ ไม่เขียนทับไฟล์เดิม หากเขียนไฟล์ล้มเหลวจะรายงานจำนวนไฟล์ที่เขียนแล้ว

ระบบเก็บสถานะของรอบใน CustomProperties ของ NormalizedInput โดยไม่เพิ่มคอลัมน์ใน A:H หากเปลี่ยน B2, A2 หรือค่าตั้ง Database ของ SKU ในรอบ ต้อง Translate ใหม่ก่อน Load/XML ข้อมูล normalized จากโค้ดรุ่นเดิมต้อง Translate ใหม่เช่นกัน เมื่อแก้ input, normalized หรือชีตผลลัพธ์ด้วยมือ ให้ทำ Translate → Load Data → Export XML ใหม่เสมอ การบันทึกสถานะไม่ได้ตรวจจับการแก้ข้อมูลด้วยมือทั้งหมด ปุ่ม Clear Data ล้างข้อมูลแถว 2 ลงไปของทุกชีต SKU ที่ระบุใน Database โดยไม่ขึ้นกับ Platform หรือสถานะ Translate เก็บหัวตารางและชีตประกอบไว้ และตรวจปลายทางทุกชีตก่อนเริ่มล้าง และทำให้ต้อง Load Data ใหม่ก่อน Export

โค้ดที่แก้ยังเป็น source สำหรับนำเข้าหรือวางแทนในโมดูลชื่อเดิมของสำเนา development `.xlam` ไม่ได้ build หรือติดตั้ง add-in ให้ ไฟล์ `.xlsm` ที่ให้มาใช้ตรวจโครงสร้างเท่านั้นและไม่ถูกแก้ไข

### การตรวจสอบก่อนใช้งาน

ต้อง Compile VBAProject และทดสอบใน Excel session แยกจาก production ดูขั้นตอนและชุดทดสอบข้อมูลสมมติที่ [tests/README.md](tests/README.md) การพัฒนารอบนี้เปิด Excel session ว่างได้ แต่เข้าถึง VBProject ผ่าน automation ไม่ได้ จึงไม่ได้ Compile หรือรันชุดทดสอบผ่าน automation และไม่ได้เปลี่ยน Trust Center ผู้ใช้แจ้งว่าทดสอบผ่านแล้วและให้ปรับเป็น v3.5.0 เมื่อ 2026-10-31 โดยยังไม่มีผลทดสอบแยกรายกรณีบันทึกไว้

ผู้ใช้แจ้งว่าโครงสร้าง input ใหม่และ Clear Data ทุก SKU ใช้งานได้ และอนุมัติ v3.5.1 เมื่อ 2026-11-01 โดยยังไม่มีผลทดสอบแยกรายกรณีบันทึกไว้ Codex ไม่ได้ Compile หรือรันชุดทดสอบผ่าน automation ในรอบนี้

## การเพิ่ม OID (v3.4 — โครงสร้างเดิมสำหรับอ้างอิง)

รายละเอียดด้านล่างเป็น workflow ทีละ SKU ของ v3.4; source ปัจจุบันใช้โครงสร้างหลาย SKU และคอลัมน์ input ตามส่วนด้านบน

OID คือเลขออร์เดอร์เดิมจากคอลัมน์ B ของ `AutoLoad-Input` เก็บและเขียนเป็น Text เพื่อรักษาศูนย์นำหน้าและเลขยาว ส่วน Barcode ยังคงเข้ารหัสด้วย `CODE128_LIBRE` ตอน Load Data

ใช้เทมเพลตที่เพิ่ม OID แล้ว โดยปรับตำแหน่งดังนี้:

| ชีต | ตำแหน่ง | ข้อมูล |
|---|---|---|
| AutoLoad-Input | B1 | SKU ที่เลือก |
| AutoLoad-Input | A3 | จำนวนชุดต่อแถว |
| AutoLoad-Input | B3:E3 | จำนวนสำเนา NameA–NameD |
| AutoLoad-Input | F3 | จำนวนสำเนา OID (0 คือไม่เขียน OID) |
| AutoLoad-Input | G3 | จำนวนสำเนา Barcode |
| AutoLoad-Input | H3 | วันที่ |
| AutoLoad-Input | I3 | Platform / รหัสร้าน |
| NormalizedInput | A:H | SKU, NameA, NameB, NameC, NameD, OID, Barcode, Qty |

ข้อมูลต้นทางแถว 5 เป็นต้นไปยังใช้ A=SKU, B=Order ID, C=Qty, D=Raw Input เหมือนเดิม หาก F3:I3 อ้างอิงสูตรจากชีต Database ต้องปรับสูตรในเทมเพลตให้ตรงกับคอลัมน์ที่เพิ่มด้วย ซอร์สนี้อ่านค่าจาก AutoLoad-Input โดยไม่ได้แก้ไข Database หรือสูตรให้

ชีต SKU ต้องมีคอลัมน์ข้อมูลแต่ละชุดตามลำดับ NameA → NameB → NameC → NameD → OID → Barcode โดยจำนวนคอลัมน์แต่ละประเภทตรงกับ B3:G3 และทำซ้ำตาม A3 เช่น เมื่อมีชื่อหนึ่งช่อง, OID หนึ่งช่อง และ Barcode หนึ่งช่องต่อชุด:

```text
N1-A1 | N1-OID | N1-BC | N2-A1 | N2-OID | N2-BC | DATE | SHOP | SKU | FN
```

ชื่อหัวคอลัมน์ต้องไม่ซ้ำกันและตรงกับตัวแปรใน Illustrator โดย OID ใช้ `Nx-OID` และ Barcode ใช้ `Nx-BC` ให้เพิ่มเลข x ตามแต่ละชุด คอลัมน์ DATE, SHOP, SKU, FN อยู่หลังข้อมูลทุกชุดและค้นหาตามชื่อหัวคอลัมน์ จึงย้ายตำแหน่งได้ตามขนาดชุดใหม่

โค้ดไม่แทรกคอลัมน์หรือสร้างหัวตารางใน workbook ให้ เมื่อปรับเทมเพลตแล้วให้เรียก Translate Input → Load Data → Export XML ใหม่ตามลำดับ อย่าใช้ข้อมูล NormalizedInput จากโครงสร้างเดิม Export XML อ่านหัวคอลัมน์และส่งออก OID เป็นข้อความโดยอัตโนมัติ

## การตรวจสอบ OID ก่อนใช้งานจริง

ใช้สำเนา development ใน Excel แยกจาก add-in production แล้ว Compile VBAProject ก่อนทดสอบด้วยข้อมูลสมมติเท่านั้น:

1. ใช้ Order ID แบบ Text เช่น `00012345678901234567` ตรวจว่าคงค่าเดิมทั้ง NormalizedInput!F:G, Nx-OID และ XML ส่วน Nx-BC ยังเป็นข้อความบาร์โค้ดที่เข้ารหัส
2. กำหนด A3=2, NameA=1, OID=1, Barcode=1 และ Qty=3 ตรวจว่ามี 2 ชุดในแถวแรกและ 1 ชุดในแถวถัดไป โดย OID อยู่ก่อน Barcode ทุกชุด และ DATE/SHOP/SKU/FN ไม่ถูกเขียนทับ
3. ทดสอบ OID=0 และ OID=2 โดยเตรียมหัวคอลัมน์ให้ตรงจำนวนสำเนา ตรวจจำนวนและลำดับข้อมูล รวมถึง Barcode=0
4. ทดสอบ `SKU *3pcs || ALPHA *2pcs \ BETA *1pcs` กับ Qty=3 และ Qty=2 โดยแทน SKU ด้วยรหัสสินค้าสมมติที่เลือกไว้ กรณีจำนวนตรงต้องได้ OID เดียวกันทั้งสองรายการ กรณีไม่ตรงต้องไฮไลต์และข้ามกลุ่ม
5. ทดสอบชื่อเดียวไม่ระบุจำนวน, Order ID + SKU ซ้ำหลายแถว, SKU ต่างกันในออร์เดอร์เดียวกัน และ Raw Input ขัดแย้งกัน เพื่อยืนยันการรวม Qty และการเลือก SKU เดิม
6. ทดสอบชื่อไทยและ Unicode เช่น `ชื่อทดสอบ 中文 한글 😀 & < > " '` ตรวจข้อความและ XML escaping รวมถึงการขึ้นบรรทัดด้วย `||`
7. ทดลองเทมเพลตขาด OID หรือวาง OID/Barcode ผิดตำแหน่ง ตรวจว่าหยุดก่อนล้างข้อมูลเดิม และตรวจ Clear Data, Ribbon callbacks และ version label
